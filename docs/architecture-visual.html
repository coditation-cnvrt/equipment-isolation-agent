Equipment Isolation Agent Logical Architecture

The agent is a Gemini-based orchestrator around deterministic plant-safety modules. Graph, HILT, and Plant360 data feed the pipeline; deterministic validation remains the authority for isolation assurance.

Data Flow

1

Resolve Context

Load project, collection, UniGraph project id, job ids, graph traversal source.

2

Read Plant Data

Fetch JanusGraph boundary, HILT/STLM topology, bboxes, and P&ID image.

3

Select Isolation

Find candidate valves/blinds/flanges, obligations, schemes, relief, and evidence.

4

Validate

Compute assurance status and unresolved gaps deterministically.

5

Render Result

Create checklist, LOTO procedure, downstream impact, JSON, viewer, and trace.

Authority Boundaries

LLM Can Orchestrate

The model decides which tools to call, can investigate gaps, ask for OSHA guidance, and summarize results.

LLM Cannot Certify

validator.py decides the authoritative assurance status. Agent reasoning cannot mark an incomplete plan safe.

LOTO Order Is Fixed

loto.py owns the OSHA phase sequence. RAG guidance may support wording and within-phase ordering only.

Inputs And Outputs

Inputs

  • Equipment tag selected by user or API request
  • UniGraph / JanusGraph equipment and piping topology
  • Plant360 STLM/HILT geometry and P&ID image
  • Isolation policy and work scope
  • Bundled OSHA 1910.147 reference for guidance

Outputs

  • Isolation boundary and selected energy isolation devices
  • Evidence checks and deterministic assurance status
  • Detected relief points and downstream impact warnings
  • OSHA-style LOTO procedure
  • JSON payload, P&ID overlay viewer, and agent audit trace
